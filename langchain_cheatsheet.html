The whole of LangChain is one pipe.

01

The building blocks

The eight concept groups this project actually used. Each term is what it is in plain words, plus the one line to say out loud in an interview.

Chat models & messages phase 1

Chat model
The LLM you message. Project: ChatOllama (local) + a custom ChatCreateAI.
Message types
System sets behaviour · Human is input · AI is the reply · Tool is a tool result fed back. A chat is a list of these.
temperature
Randomness knob. 0 = consistent (used for classification); higher = creative.

say thisChat models take a list of typed messages and return an AIMessage.

Prompt templates phase 1 · 3

ChatPromptTemplate
A fill-in-the-blanks message form with {placeholders}.
.partial()
Pre-fill one slot ahead of time (e.g. bake in format_instructions once).
MessagesPlaceholder
A slot where a whole list of past messages gets replayed — the seat memory sits in.

say thisTemplates split fixed instructions from runtime variables, so prompts are reusable and testable.

Structured output phase 1 · 6 · 8

Schema (BaseModel)
The exact output shape — FoodQuery, ReviewClassification.
Field / Literal
Field(description=…) steers each slot; Literal[…] locks it to a fixed menu so the model can't drift.
PydanticOutputParser
Turns raw text into your validated object; errors if it doesn't fit.
format_instructions
The schema written into the prompt as text, for text-only models.
with_structured_output
The native alternative — needs a tool-calling model.

say thisBoth paths guarantee the shape of the output — never that the content is correct.

Runnables & composition core

Runnable
Anything with .invoke() — models, prompts, parsers, tools, functions.
| (pipe) / chain
Feed one output into the next; a chain is Runnables piped together.
RunnableLambda
Wrap a plain Python function so it drops into a chain.
.invoke() vs .batch()
Run once, vs run many inputs concurrently (thread pool, max_concurrency). Phase 8: 150 docs in ~57s.

say thisThe Runnable is the uniform interface; LCEL just pipes Runnables together with |.

Retrieval / RAG phase 2 · 7 · 8

Embedding / vector
Text as numbers that capture meaning (bge-m3). Similar meaning → nearby vectors.
Vector store
DB that finds nearest-meaning items (Chroma).
Document
page_content (searched by meaning) + metadata (exact facts).
Semantic vs metadata
Feels-relevant (meaning) vs is-true (filters like price<10). Use both.
Grounding
Answer only from what you retrieved; never invent.

say thisSemantic search finds meaning; metadata filters enforce truth. And RAG isn't only Q&A — retrieve + classify + aggregate is a reporting engine.

Memory phase 3

Stateless
The model remembers nothing between calls. The key insight.
"Memory"
= re-sending the transcript every turn. No magic.
session_id
Which conversation's history to load.
RunnableWithMessageHistory
Auto-loads/saves history per session. (Now deprecated → LangGraph persistence.)

say thisLLMs are stateless; memory is just replaying prior messages through a MessagesPlaceholder.

Tools & agents phase 4 · 5 · 7

@tool
A Python function the model may call. Its docstring is the instruction.
bind_tools
Makes the model aware of tools — it can request, not run them.
tool_calls → ToolMessage
Model emits a call slip (name+args); you run it, return a ToolMessage tagged by tool_call_id.
ReAct loop
Thought → Action → Observation → repeat. create_react_agent prebuilds it.
Heterogeneous tools
SQL (structured) + vectors (unstructured) in one agent.

say thisThe model requests a tool via tool_calls; my loop runs it. That's ReAct. Power comes from tool diversity, not model size.

Security: LLM + a database phase 7

Never raw SQL
Don't let the model author queries — DROP TABLE / injection risk.
Whitelist
Model picks from a fixed menu of pre-written SELECTs.
Parameterized SQL
? placeholders → values are data, never code. Injection impossible.

say thisThe model chooses what to ask; you own the query. Proven: a '; DROP TABLE orders; -- input matched zero rows and changed nothing.

03

Five lessons that keep coming back

The "what did you actually learn" answers. Each one earned by hitting it in the project.

LESSON 01

Shape ≠ content

Schemas guarantee the output's shape, never that the content is right or the phrasing is what you hoped. Fix that in the model or the tool.

LESSON 02

LLM = language, tools = truth

The model turns messy words into structure and plans; deterministic tools verify facts, do math, touch data.

LESSON 03

Tool diversity > model size

The same model gains power from different kinds of tools (SQL + vectors), not a bigger brain.

LESSON 04

Aggregates drift silently

Map-reduce reports look authoritative but wobble at fuzzy category edges — and nothing errors. Only evals tell you to trust them.

LESSON 05

Compose ≠ control

LangChain pipes steps brilliantly but can't branch, loop, pause, or persist. That gap is the whole reason for LangGraph.
